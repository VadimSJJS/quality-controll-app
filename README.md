# Quality Control App

**Система учёта и анализа несоответствующей продукции** для сталепроволочного цеха №2 (СтПЦ-2) ОАО «БМЗ — УКХ «БМК».

Программа призвана заменить устаревшую систему на базе PARADOX (1992 г.) и обеспечить:
- **Регистрацию** несоответствующей исправимой продукции и брака по всем технологическим участкам.
- **Учёт доработки** (восстановления/переназначения) продукции.
- **Формирование отчётов** по качеству за сутки, неделю, месяц, квартал, полугодие, год.
- **Построение диаграмм Парето** и гистограмм для анализа причин дефектов.

## 🔐 HTTPS и сертификаты

Приложение работает по HTTPS (порт **8082**). Чтобы браузер не показывал «Не защищено»
(перечёркнутый `https`), используется собственный внутренний корневой сертификат:
серверный сертификат на имя `devteam7` подписывается локальным CA, а сам CA устанавливается
в «Доверенные корневые центры сертификации» на сервере и на ПК пользователей.

Порядок действий:

1. **Выпуск сертификатов** — `.\create-devteam7-certificate.ps1`
2. **Сборка и запуск на сервере** — `.\mvnw.cmd -DskipTests package` и `start-server.bat`
3. **Установка доверия** (на сервере и на каждом ПК, либо через GPO) — `.\install-devteam7-cert.ps1`
4. **Проверка** — `.\check-server-certificate.ps1 -ServerName devteam7`

Подробная инструкция, диагностика типичных ошибок Chrome и вариант с корпоративным УЦ:
[HTTPS-SETUP.md](HTTPS-SETUP.md)

## 🖥️ Локальный запуск и сервер (одна папка — два режима)

Приложение настраивается файлами окружения, которые читаются из рабочего каталога:

| Файл | Где применяется | Что содержит |
| --- | --- | --- |
| `.env` | везде (и на сервере) | доступы к БД и **боевые** настройки HTTPS (боевой `.pfx`) |
| `.env.local` | **только на вашем ПК** (в git не попадает) | локальные перекрытия: встроенный в jar кейстор, свой порт |

Порядок чтения: `.env` → затем `.env.local`, который **перекрывает** значения из `.env`.
На сервере `.env.local` нет, поэтому там всегда действует боевая конфигурация и работающая
ссылка `https://devteam7:8082/` не затрагивается.

**Локальная разработка:**

```bat
.\mvnw.cmd -q clean package -DskipTests   :: собрать jar
start-local.bat                            :: запустить локально -> https://localhost:8082/
```

или без сборки jar:

```bat
.\mvnw.cmd spring-boot:run
```

Локально используется встроенный кейстор (`classpath:keystore/keystore.p12`), сертификат тот же
`CN=devteam7` с `localhost` в SAN, поэтому браузер не ругается — при условии, что корневой
сертификат проекта установлен на ПК (`.\trust-root-ca.bat`).

**Обновление сервера:**

```bat
.\mvnw.cmd -q clean package -DskipTests
:: скопировать target\quality-control-app-0.0.1-SNAPSHOT.jar на сервер (и сам start-server.bat,
:: если он менялся), затем на сервере запустить start-server.bat
```

⚠️ Файлы `.env` и `.env.local` на сервер/с сервера копировать не нужно — они настраиваются
на месте: `.env` (с боевым `.pfx`) на сервере, `.env.local` у вас локально.
